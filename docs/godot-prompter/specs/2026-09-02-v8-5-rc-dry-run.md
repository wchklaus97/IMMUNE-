This run proved that the accepted V8.5 T sculpt can be imported, packaged,
loaded, instantiated, animated, and exercised through the Web and macOS

publish anything.

The checked-in project remains `immune/visual/gel_look="v8_3"`. The checked-in
Web and macOS export presets still exclude the V8.5 GLB. All promotion changes
were made in an exact-HEAD source overlay below:

`outputs/v8-5-rc-dry-run-f3eac5f/source-overlay/godot/immune/`

The overlay changed only the following release inputs:

1. selected `v8_5` instead of `v8_3`;
2. removed the accepted r4 GLB from the Web/macOS exclusion list while leaving
   all Meshy, Tripo, V8.4, fix, and concept assets excluded;
3. added the `v8_5_rc_dry_run` custom feature;
4. enabled an overlay-only export plugin that SHA-checks and inserts the raw
   GLB at its exact `res://` path;
5. excluded `addons/*` from the runtime pack so editor-only plugin code did not
   leak into the game.

No push, tag, upload, notarization, Steamworks change, or public release was
performed.

## Failure-driven packaging correction

A normal Godot export stores an imported GLB's derived scene and `.import`
metadata, but not necessarily the original raw GLB bytes. The V8.5 loader is
intentionally stricter: it calls `FileAccess.get_sha256()` on the raw source
before accepting the imported `PackedScene`. The first exported PCK therefore
contained the imported scene but failed the exact source-file contract.

Adding the GLB to `include_filter` did not solve the problem. Godot's
[export documentation](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)
states that the non-resource filter is for files that are not imported
resources; imported resources are handled by the import/export pipeline. The
corrected overlay uses
[`EditorExportPlugin.add_file()`](https://docs.godotengine.org/en/latest/classes/class_editorexportplugin.html#class-editorexportplugin-method-add-file)
to insert the 288,900-byte raw GLB at the exact virtual path after checking its
immutable SHA-256. The plugin is feature-gated and is excluded from the runtime
PCK.

The successful R4 export log contains:

`V8_5_RAW_EXPORT_ADDED path=res://characters/base_t/CHAR-BASE-T-v8-5-authored-sculpt-r4.glb bytes=288900 sha256=8f14...9294`

The final Web and macOS PCKs each contain exactly 520 paths, including exactly
these three V8.5 entries:

- the imported `.scn`;
- the raw `.glb`;
- the `.glb.import` metadata.

The two platform PCK files are byte-identical:

`800883bab6d864dbf51dfe0c872e0f8b9d07fa54a3d2bf821883d6f2f712417d`

No Meshy B/M, Tripo T, T fix, V8.4 single-mass, or concept resource leaked
into either pack.

## Promotion decision and remaining gates

The technical Web/macOS dry run is complete. It does **not** make the game 100%
public-release ready. The following gates remain intentionally open:

1. authorized owner signature for asset rights and final art-direction approval;
2. reviewed production integration of the raw-source export step before V8.5
   becomes the default;
3. Developer ID signing, notarization, and Gatekeeper verification;
4. exact-candidate Windows and Linux exports and native smoke tests;
5. real Steam App/depot IDs, SteamCMD preview, and private-branch installs;
6. minimum-spec, Steam Deck, and human playtest acceptance;
7. Valve review and explicit owner authorization to release publicly.

Until those close, V8.3 remains the shipping default and R4 remains a preserved,
non-shipping V8.5 promotion candidate.
